# 本项目 Playwright 自动化测试专属规则

## 业务背景
**HIS 系统**（医院信息系统）- 门诊医生站业务自动化测试

**核心业务流程**：
```
登录 → 选科室 → 医生站 → 接诊 → 写病历 → 开诊断 → 开处方 → 结束就诊
```

## 1. 项目结构
- **pages/** - 页面模型 POM（BasePage 基础页、LoginPage 登录、DoctorPage 医生站）
- **tests/** - 测试用例（冒烟测试、完整流程测试）
- **utils/** - 工具方法
- **test-data/** - 测试数据

## 2. 用例规范
- 每个用例包含成功、失败场景
- 用 async / await 写法
- 不使用 TS 类型
- **冒烟测试**：2 分钟内完成核心链路验证
- **用例独立**：可单独运行，不依赖其他用例

## 3. 代码风格
- 变量、函数用小驼峰：`patientName`, `selectDepartment()`
- 代码简洁、不冗余
- 不使用复杂语法
- **断言必须有描述**：`expect(page).toHaveURL(/预期/, '应跳转到首页')`

## 4. 登录状态管理
- 使用 `login.fixture.js` 复用登录状态，避免重复登录
- 浏览器缓存存放在 `browser-data/`
- 缓存失效时删除该目录重新登录

## 5. 输出要求
- 告诉我文件应该放在哪个目录
- 代码可直接复制运行
- 不使用 TS、interface、类型定义

## 6. 提交规范
- 提交信息格式：`<类型>: <描述>`
- 支持的类型：feat（新功能）、fix（修复bug）、docs（文档）、style（格式）、refactor（重构）、chore（构建过程）、revert（版本回退）、perf（性能优化）、test（测试）
- 提交信息示例：`feat: 增加退费流程测试`、`fix: 修复处方开立选择器失效`
- 提交前检查：代码通过测试，提交信息符合规范，改动内容与提交信息一致
- 工具支持：项目已配置 commitlint 和 husky，会自动检查提交信息是否符合规范
