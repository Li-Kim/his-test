# 本项目 Playwright 自动化测试专属规则

## 业务背景
**HIS 系统**（医院信息系统）- 门诊医生站业务自动化测试

**核心业务流程**：
```
登录 → 选科室 → 医生站 → 接诊 → 写病历 → 开诊断 → 开处方 → 结束就诊
```

## 1. 项目结构
- **pages/** - 页面模型 POM（BasePage 基础页、LoginPage 登录、DoctorPage 医生站）
- **tests/** - 测试用例（冒烟测试、完整流程测试）
- **utils/** - 工具方法
- **test-data/** - 测试数据

## 2. 用例规范
- 每个用例包含成功、失败场景
- 用 async / await 写法
- 不使用 TS 类型
- **冒烟测试**：2 分钟内完成核心链路验证
- **用例独立**：可单独运行，不依赖其他用例

## 3. 代码风格
- 变量、函数用小驼峰：`patientName`, `selectDepartment()`
- 代码简洁、不冗余
- 不使用复杂语法
- **断言必须有描述**：`expect(page).toHaveURL(/预期/, '应跳转到首页')`

## 4. 登录状态管理
- 使用 `login.fixture.js` 复用登录状态，避免重复登录
- 浏览器缓存存放在 `browser-data/`
- 缓存失效时删除该目录重新登录

## 5. 输出要求
- 告诉我文件应该放在哪个目录
- 代码可直接复制运行
- 不使用 TS、interface、类型定义

## 6. 提交规范
- 提交信息格式：`<类型>: <描述>`
- 支持的类型：feat（新功能）、fix（修复bug）、docs（文档）、style（格式）、refactor（重构）、chore（构建过程）、revert（版本回退）、perf（性能优化）、test（测试）
- 提交信息示例：`feat: 增加退费流程测试`、`fix: 修复处方开立选择器失效`
- 提交前检查：代码通过测试，提交信息符合规范，改动内容与提交信息一致
- 工具支持：项目已配置 commitlint 和 husky，会自动检查提交信息是否符合规范

## 7. 元素定位选用统一规范
### 7.1 定位优先级（严格按顺序优先选用）
1. `getByRole`：适配按钮、下拉、弹窗、菜单栏等功能性元素
2. `getByLabel` / `getByPlaceholder`：优先用于所有表单输入类元素
3. `getByTestId`：存在自动化专属测试属性时首选，稳定性最高
4. 单一稳定固定类名定位：选取框架原生、长期不会改动的class
5. 多类名组合定位：同一元素多个稳定类名，采用**无空格连写**写法
6. `filter({hasText})` / 文本匹配：仅文案固定无变更场景使用，优先正则模糊匹配
7. 父子层级定位：仅重复结构元素区分场景使用
8. 下标定位 `.first()`/`.nth()`：仅作为最后兜底方案，尽量少用

### 7.2 多类名元素定位规则
1. HTML 内 `class="tiptap ProseMirror umo-editor"` 空格分隔，代表元素拥有多个独立类名
2. 定位写法：多个类名直接相连书写，**禁止加空格**，示例：`.tiptap.ProseMirror`
3. 筛选原则：保留编辑器框架原生固定类，剔除项目自定义业务类、Vue动态哈希类`data-v-xxx`
4. 禁止用法：完整class字符串精准匹配、空格分隔写成父子选择器

### 7.3 业务常用元素固定定位写法
1. 功能按钮（取消、关闭、确定、接诊）
```js
getByRole('button', {name:/取消|关闭|确定|接诊/})
```
2. 诊断类型选择按钮
```js
getByRole('button', {name:new RegExp(`请选择${type}诊断`)})
```
3. 病历富文本编辑器
```js
locator('.tiptap.ProseMirror')
```
4. 弹窗内部操作按钮：以弹窗容器为父级再进行定位

### 7.4 禁止使用的定位方式
1. 禁止使用Vue动态生成哈希类、临时样式类进行元素定位
2. 禁止书写过长绝对层级路径定位元素
3. 禁止大量依赖下标定位，易受页面元素顺序变动影响
4. 禁止使用易变动业务文案作为唯一定位依据

### 7.5 智能选用判断逻辑
编写元素定位时自动判定：
1. 页面按钮类 → 统一使用角色定位`getByRole`
2. 表单输入框 → 优先标签/占位符定位
3. 编辑器、第三方组件 → 选取组件自带稳定类名组合定位
4. 无标准语义属性元素 → 采用过滤文本方式匹配
5. 所有通用规则无法匹配时，再使用层级、下标兜底定位
